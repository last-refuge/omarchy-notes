Omarchy Notes roadmap

A native, local-first notebook for Omarchy. It aims for Apple Notes' fast capture and rich documents, drawn in your active theme. Version 1.0.0 is ready to ship: packaged for Arch, accessible, and every performance target met on a 10,000-note library.

Milestones

What each one delivers

Each milestone ends on an exit condition, not a date. Once the document contract is stable, two engineers can split storage and UI work, but the editor still sets the critical path.

Editor and storage proof

Done · 23 Sep2–3 eng-weeks

Exit: mixed-content editing round-trips without loss; undo, IME, accessibility and crash-recovery tests pass; toolkit decision recorded (docs/decisions/0001).

Where things stand

Settled, and carried forward

Kickoff decisions

v1 scope
Local-only. No sync, locking or collaboration; stable ids and revisions keep sync possible later.
Visual target
A familiar three-pane Notes layout in the active Omarchy theme, not an Apple recreation.
Audience
Personal first, but every choice must hold for the public app that follows.
Editor toolkit
Qt Quick TextEdit over an owned QTextDocument.
Still open
The macOS reference version for parity, and which Omarchy releases to support. (App ID settled: org.omarchy.Notes.)

Known gaps

  • Theme and font changes rebuild the document and clear undo history.
  • Image decoding runs on the UI thread during note load.
  • Very large notes open in ~0.9 s at 3,000 blocks (offscreen); re-measure on real hardware.
  • Drag and drop: notes move between folders by menu for now; dragging notes and folders comes later.
  • Manual desktop checks: fcitx5, Orca, fractional scaling, portal file dialogs.
Release gates

What v1 must prove

Targets are benchmarked on a documented reference machine with a 10,000-note / 1 GB attachment fixture. Spike measurements come from offscreen runs with software rendering, so they are indicative only.

Editing

Round-trip a fixture library: nested lists, check states, tables, note links, images, attachment metadata, emoji, RTL, IME and long documents. Unsupported import content is reported, never discarded.

Reliability

Inject failures during save, attachment import, migration and backup. Kill and reopen at persistence boundaries; every acknowledged save must survive. Test full-disk and read-only storage.

Accessibility

Capture, edit, organize, search and export using only the keyboard. Screen-reader names and structure, visible focus, large text, reduced motion, readable contrast across themes.

After v1

Expansion, in order

Outside the v1 estimate. Each step gets its own acceptance and resource-budget tests.

  1. Private and searchable media

    Encrypted locked notes (content, attachments, revisions and previews protected together, with a dedicated security review), PDF text extraction and OCR, annotation and drawing.

  2. Audio and math

    Recording, offline transcription after an explicit model download, searchable transcripts, and a constrained math parser. Expensive work stays cancellable and off the UI thread.

  3. Device sync

    Choose platforms and a transport; authentication, attachment transfer, offline edits, deletion propagation, conflict recovery and encryption. Never sync the live SQLite file as the protocol.

  4. Collaboration

    Prove a CRDT (or equivalent) merge model on rich documents first, then permissions, invitations, concurrent editing, activity and mentions.

  5. Ecosystem conveniences

    Browser capture, an optional shell widget, richer importers, and optional writing help through a replaceable provider.
